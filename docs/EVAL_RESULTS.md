## 1. Retrieval: does search find the right clause?

**Recall@k** = share of the correct clauses that appear in the top *k* results. **MRR** = how high the first correct clause ranks on average (1.0 = always first).

## 3. AI agent vs baseline: partial run on Groq (`openai/gpt-oss-120b`)

_Measured 2026-10-21 on **2 of the 6 regulations** (`reg-01-data-protection`, `reg-04-card-tokenisation`;
8 labelled requirements). The full six-regulation AI run was stopped early because Groq's free tier
rate-limits it to ~3 minutes per regulation. Treat this as a small sample, not a final score.
Re-run with `python -m policypilot eval` to fill in all six._

| Metric (same 8 requirements) | Demo baseline (no AI) | AI agent (Groq) |
|---|---|---|
| Precision | 11/13 (85%) | **9/9 (100%)** |
| Recall | 8/9 (89%) | 8/9 (89%) |
| Impact accuracy | 3/7 (43%) | **7/7 (100%)** |
| Quotes valid — first draft | 100% | 17/18 (94%) |
| Quotes valid — final | 100% | **18/18 (100%)**, 1 quote fixed by the fact-check loop |
| Cost | free | ~17k tokens and 7 turns for the 3-requirement regulation |

**What this shows:** retrieval already finds the right clauses, which is why recall is the same.
The AI adds the *judgement*: it labels every clause correctly and doesn't flag unrelated ones.
The fact-checker caught one quote the model got wrong and the model fixed it, so every quote
shown to the reviewer is real.

The one recall miss is the same requirement in both columns: for "customer consent for
tokenisation", the label points at the card-storage clause (`info-security§3.2`). The AI chose the
consent clause (`data-privacy§2.1`), which the labels accept as an alternative. The baseline chose
that clause too, but also flagged an unrelated authentication clause (`info-security§2.2`).
